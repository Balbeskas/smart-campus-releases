## 1. Описание релиза и бизнес-цель
Колонка `price` в таблице чеков хранит не цену товара, а **итоговую сумму чека**. Из-за этого
бухгалтерия и отдел питания путают её с ценами позиций меню при сверке льготного питания.
Релиз переименовывает колонку в `amount` и вводит единый цифровой след: каждая оплата получает
в трассе теги `jira.issue=CAMPUS-104` и `campus.check_id`, по которым служба поддержки находит
спорный платеж студента за минуты, а не по журналам кассы.

Переименование выполняется по паттерну **Expand and Contract** в три независимых шага,
поэтому столовая не останавливается ни на одном из них.

## 4. План отката (Rollback Plan)
Триггеры отката: sanity-тест упал; доля 5xx > 1 % за 5 минут; расхождение сумм в контрольном запросе.

1. Откат приложения на v1.8.4 (старые поды читают и пишут `price`, которая еще на месте):
   ```bash
   kubectl rollout undo deployment/canteen-payments -n campus
   kubectl rollout status deployment/canteen-payments -n campus --timeout=120s
   ```
2. Данные не теряются: v1.9.0 писала сумму **в обе колонки**, поэтому `price` содержит все чеки,
   созданные во время релиза.
3. При необходимости откатить схему: `ALTER TABLE canteen_checks DROP COLUMN IF EXISTS amount;`
   (только после отката приложения).
4. Фаза Contract необратима без восстановления из дампа — поэтому она вынесена в отдельное окно
   и защищена проверкой в начале `03_contract.sql`.
